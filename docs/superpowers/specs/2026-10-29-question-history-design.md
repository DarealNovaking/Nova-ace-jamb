# Question history and safe restoration

Continue FCB-03 under the owner's delegated routine implementation decisions. The text editor/CSV importer is deployed, historical snapshots already exist, and two genuine saved browser profiles have now passed read-only access checks. The owner requires both profiles remain signed in and authorized a total $2 TinyFish budget. No production question mutation, role change, new migration installation or deployment is included in this implementation without a concrete release approval.

## Design

Expose immutable question snapshots through a new guarded `ace.question_history(uuid,integer)` RPC: authorized admin/editor only, trusted owner, read committed, role lock and question row SHARE lock for coherent current revision. Cursor pagination is descending, ten snapshots per page, with strict current/question identity readback. No direct table grants. Historical answers remain restricted to editorial roles.

Restore via `ace.restore_question(uuid,integer,integer,text)`: authorized author/editor or administrator, expected current revision, older source revision, required reason (1–2000 trimmed characters). Read only the requested immutable snapshot and rebuild an allowlisted draft. Reject any media that the current text workflow cannot safely restore. Invoke the existing `manage_question('save',...)` to preserve its active-taxonomy, duplicate, ownership, published-edit, concurrency, immutable history and audit guards. A successful restore creates exactly one new revision, resets rights/reviewer/publication, preserves question identity and original creator, records an additional `question_restored` audit entry and requires independent review again. Restore never activates historical publication flags or removes previous snapshots.

UI: a Version history button per question opens a bounded ten-record page with state/revision/time and safely rendered content, options, explanation and source evidence. Authors/admins may restore older versions only while the current question is private; a published question explains withdrawal is required. Require a reason, disable concurrent question/import/editor mutations while history is open, freeze restore after any uncertain response and require queue refresh. A stale current revision also blocks restore. Read failures have a retry path, and pagination never implies all history has been loaded. Session signout/account-change unmount guards prevent stale UI readbacks. Production profiles must never be signed out by automation; synthetic browser regression tests may continue testing signout using mocked sessions only.

Alternatives: client resubmission of arbitrary old snapshots obscures restoration intent; direct table access violates existing guards. Reuse existing mutation authority and add narrowly scoped history/restore RPCs rather than expand the original action enum or duplicate lifecycle code. Media/rich content/moderation and the first reviewed dataset remain separate FCB-03 work.
