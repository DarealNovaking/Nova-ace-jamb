# ACE catalog recovery baseline

`ace-2026-10-27.sql` is a schema-only snapshot of the live `ace` application schema after eleven specifically authorized FCB-01 migrations (six earlier fixes plus the staged CBT bundle). It lives outside `migrations/` and must never be included in a production migration push. `CREATE SCHEMA ace` intentionally refuses an existing schema. There are no top-level DROP statements, data mutations or ledger edits. Function bodies retain their application logic but are not executed by recovery. No credentials or user records are included.

The provenance file `ace-2026-10-27.catalog.json` was read through PostgreSQL catalog queries from project `uokiqlgmzprqfbzmedaz` on 27 October 2026 (PostgreSQL 17.6). It records 467 columns, 229 constraints, 82 additional indexes, 39 functions, 82 policies, 51 RLS tables, eleven application triggers (including the `auth.users` signup trigger) and observed API ACLs. All application objects are owned by `postgres`. No column ACLs, custom standalone types, sequences, inheritance, table storage options or schema-specific default ACLs existed. The renderer refuses these currently unsupported features if they appear in a future input snapshot.

Prerequisites are an **empty disposable database**, the `postgres` owner, Supabase `anon`/`authenticated` roles and `auth.users`/`auth.uid()`/`auth.jwt()` contracts, plus pgvector in `extensions`. The baseline assumes those platform objects already exist; it neither replaces nor reconstructs Supabase Auth. The test fixture creates minimal synthetic auth contracts only in the disposable database. Vector retains its real `vector(768)` type. Other installed project extensions are recorded as provenance, but no application object requires their additional extension objects.

Run `python3 scripts/render-ace-schema-baseline.py` to render deterministically from the committed metadata. Run the SQL fixture and `python3 tests/sql/fcb_01_schema_parity.py` against a disposable PostgreSQL service using the dedicated Verify CI job. The parity check compares every captured definition and non-owner ACL, rather than counts alone. PostgreSQL 18's additional NOT NULL constraint catalog entries are excluded because column nullability is compared separately; PostgreSQL 17's owner MAINTAIN ACL bit is ignored when comparing PostgreSQL 16. API privileges are never ignored. Native CI uses PostgreSQL 17 with pgvector 0.8.7; production provenance has pgvector 0.8.2, so this is schema/behavior replay, not an exact engine/extension binary replica.

This closes current-schema reproduction separately from historical migration recovery. It does **not** prove the incomplete historical migration chain can replay, change the live migration ledger, restore data, establish content rights or enable the retired catalogue workflow. Legacy objects are preserved solely for faithful recovery. Existing fail-closed operational table grants are preserved. The reviewed CBT APIs now enforce owner/paper/resource boundaries and require approved runtime/content policies before use.
